## Implementation

`experiments/v2_pilot_protocol.py` verifies the design, exact job configurations and historical source pins. It binds current clean executing source, commit, package versions, Python, lock files and host metadata to a separate external approval. `experiments/v2_pilot.py` and `scripts/run_v2_goes_pilot.py` provide the serial production driver. Its default mode returns metadata only; `--execute` without a complete separately approved declaration is refused before scientific I/O or output creation.

`experiments/v2_pilot_worker.py` reuses the frozen May–July loader, existing controlled JEPA/supervised/frozen models, TCN and quantile-linear trainers. Every model receives its full explicit typed configuration. Workers establish CPU float32, four native-library/Torch threads, deterministic algorithms and fixed seeds. Preparation rechecks raw/native identities and actual dataset/spec/split/training/normalization/subset/validation-content fingerprints. Those production checks are implemented; scientific preparation is not executed in this milestone.

The exact20 process jobs contain two shared SSL jobs,14 primary models and four alternate-loss models. JEPA jobs require the successful sealed same-seed SSL artifact, with source/environment/configuration bindings; missing or changed dependencies fail instead of triggering SSL recomputation. Workers save new weights-only artifacts and require exact canonical validation prediction parity after reload. Existing checkpoints are never selected as output destinations.

The driver reuses `ProcessSupervisor`, explicitly supplies zero retries, checks the1GiB free-output-storage floor before launch and each attempt, samples worker plus descendant RSS against2GiB, and applies the7200s total wall deadline through finalization. The worker command canonically imports its module so the existing executed-source attestation remains valid; `python -m` execution is not used by the driver. It imports complete sealed model payloads into separate14-job and4-job `DevelopmentRun`s, runs mandatory actual-fitting guards, selects every planned model and stops at `D_LOCKED`. Test release remains disabled. Both guarded runs and reports are prepared under `OUTPUT/.publication-staging`; one atomic directory rename exposes `OUTPUT/publication` only after both succeed. Completion accounting is `OUTPUT/publication/pilot_accounting.json`. Failure retains staging and an `OUTPUT/pilot_failure.json` engineering report. Any failed/pending process, integrity failure, interruption or resource exhaustion blocks ordinary completed-pilot publication. Existing output directories are refused; there is no automatic resume route.

`experiments/v2_pilot_reporting.py` derives strict finite descriptive reports from all18 canonical model/evaluation payloads and all20 successful first attempts. It reports all seven primary contrasts, alternate J−S and two within-arm bundled loss-recipe comparisons; full marginal predictive diagnostics, median errors, selection histories and budgets are retained. Sampling-inference fields remain null with `NO_VALIDATED_REPLACEMENT` reasons. Regeneration validation rejects extra report fields, aliases and altered derived values. Actual pilot costs count each SSL process once; attributed JEPA recipe views must not be summed as actual pilot costs.
